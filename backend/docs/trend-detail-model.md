# 트렌드 상세 조회 저장 모델

S15P21A102-178의 확정 API는 `GET /trends/{trendId}`이다. 기존 dev에 트렌드 Entity가 없어 API에 필요한 저장 모델을 추가했다. 임시 ERD SQL은 구현 기준으로 사용하지 않는다.

| 테이블 / 매핑 | 저장하는 값 |
| --- | --- |
| `keywords` / `Keyword` | 키워드 ID, 이름, 기존 `member.domain.Domain` Enum 문자열 (`DEVELOP`, `FASHION`) |
| `trends` / `Trend` | 트렌드 ID, 키워드 FK, 한 줄 설명, 최초 탐지 시각 |
| `trend_daily_analyses` / `TrendAnalysis` | 트렌드 FK, 트렌드 유형, 최근·직전 언급량, 두 24H 구간, 분석 시각 |
| 위 분석 테이블에 임베딩 / `TrendEvidence` | 실제 적용한 규칙 버전·설명, 숫자 임계값 JSON, 데이터 완전성 상태 |
| 위 분석 테이블에 임베딩 / `TrendAiAnalysis` | 실제 AI 상태, 요약, 이유, 생성 시각 |
| `trend_analysis_sources` | 분석 FK, 실제 AI 입력 콘텐츠 ID 목록과 순서 |

`growthAmount`와 `growthRate`는 저장된 언급량으로 계산하며 중복 컬럼을 만들지 않는다. 증가율은 소수 첫째 자리까지 HALF_UP 반올림하고, 이전 언급량이 0이면 null이다.

분야 Enum은 중복 정의하지 않는다. 기존 Enum에 표시명 접근자가 없으므로 트렌드 응답 DTO에서 코드별 표시명만 매핑한다. 회원 코드는 변경하지 않는다.

분석은 고정 24H 전용 테이블에 저장한다. 모델 생성 시 최근·직전 구간이 각각 정확히 24시간이고 연속인지 검증한다. API는 해당 트렌드의 `analyzed_at DESC, id DESC` 첫 결과를 읽는다. 요청 시각으로 새로운 구간을 꾸미거나 실시간 집계를 수행하지 않는다.

분석이 없으면 기본 정보를 유지하고 분석 필드를 모두 null로 반환한다. 분석이 있는 경우에도 근거나 AI 결과가 없으면 해당 객체는 null이다. 분석 상태·규칙·임계값·출처·시각의 실제 값은 분석 생산자가 저장해야 하며, 조회 API는 이를 추정하지 않는다. `description`은 트렌드 기본 정보, AI 요약은 선택한 분석 스냅샷의 값이다.

현재 콘텐츠 Entity가 없으므로 AI 출처는 실제 입력 콘텐츠의 ID 값 목록으로만 저장한다. 콘텐츠 모델을 임의로 만들거나 키워드의 모든 관련 콘텐츠를 AI 출처로 대체하지 않는다. 콘텐츠 테이블에 대한 FK 및 검증은 해당 저장 모델과 연동할 때 정해야 한다. 이 작업에는 콘텐츠 조회 API와 분석 생산 파이프라인이 포함되지 않는다.

JPA 매핑이 새로운 저장 구조를 정의한다. 운영 DB에는 배포 전 해당 테이블을 반영해야 한다. 테스트 데이터만으로 API를 구현하지 않으며, 서비스 코드에 초기 데이터나 가짜 분석값을 삽입하지 않는다.

조회 서비스의 읽기 전용 트랜잭션 안에서 키워드·분석·AI 출처를 DTO로 변환한다. 기본 정보 조회는 키워드를 EntityGraph로 함께 읽고, 최신 분석 조회에는 트렌드·분석 시각·ID 인덱스를 둔다.

테스트는 성장·감소·0 기준값, 24H 구간 제약, 분석 미존재, 두 분야, 최신 분석 선택과 시각 동률, 영속화 후 JSON 근거·AI 출처 복원, HTTP 성공·검증·404 및 REST Docs를 검증한다. 현재 인증 설정의 403 차단도 확인하며, 명세상 401과 실제 JWT 검증은 인증팀 연동 사항이다.
