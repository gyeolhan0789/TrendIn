[[trends]]
== Trends

[[trends-list]]
=== 분야별 트렌드 조회

`GET /trends?domain={domain}&type={type}&period={period}&page={page}&size={size}`

분야(`DEVELOP`, `FASHION`), 트렌드 유형(`CURRENT`, `NEW`, `RISING`), 기간(`24H`, `7D`, `30D`)은 필수다.
기간은 다른 트렌드 API와 같은 `Asia/Seoul` 기준 완료 구간을 사용하며, `keyword_metrics`에서 해당 구간의 지표를 반환한다.
페이지 번호의 기본값은 0, 페이지 크기의 기본값은 20이다.

==== 요청 및 응답

operation::trends-list[snippets='http-request,request-headers,query-parameters,http-response,response-fields']

요청한 `type`이 `trends.trend_types`에 포함된 트렌드만 조회한다.
`CURRENT`는 언급량 내림차순, `NEW`는 트렌드 갱신 시각 내림차순,
`RISING`은 저장된 증가율 내림차순으로 정렬한다. 증가율이 `null`인 항목은 뒤에 둔다.
같은 정렬 값에서는 트렌드 ID 오름차순을 적용해 페이지 결과를 고정한다.
조건에 맞는 지표가 없으면 200과 빈 `content`를 반환한다.

[[trends-detail]]
=== 트렌드 상세 조회

`GET /trends/{trendId}?period={period}`

`period`는 필수이며 `24H`, `7D`, `30D`만 허용한다. 대시보드에서 선택한 기간을 그대로 전달한다.
상세 지표는 `Asia/Seoul` 기준 완료 구간과 일치하는 `keyword_metrics`의 기간 지표를 사용한다.
`description`은 트렌드의 짧은 설명이고, `summary`와 `reason`은 `trends`에 저장된 최신 상세 분석 결과다.
`trendTypes`는 현재 트렌드에 적용된 `CURRENT`, `RISING`, `NEW` 유형 목록이다.
분야는 기존 회원 도메인의 `DEVELOP`, `FASHION` 코드를 사용하며 중분류는 없다.

==== 요청

operation::trends-detail[snippets='http-request,request-headers,path-parameters,query-parameters']

==== 200 OK

operation::trends-detail[snippets='http-response,response-fields']

분석 구간은 `Asia/Seoul` 자정 기준의 완료된 연속 구간이며, 요청 기간과 그 직전 동일 기간을 비교한다.
증가량은 요청 기간 언급량에서 직전 동일 기간 언급량을 뺀 값이다.
증가율은 `(증가량 / 직전 언급량) × 100`을 소수 둘째 자리에서 반올림하여 소수 첫째 자리까지 표시한다.
직전 언급량이 0이면 `growthRate`는 `null`이다.
시각은 오프셋을 포함하는 ISO 8601이며 분석 구간은 시작 포함, 종료 제외이다.

==== 200 OK — 요청 기간 지표 없음

트렌드가 존재하면 기본 정보를 반환한다.
언급량·증가량·증가율과 `analysisWindow`는 모두 명시적인 `null`이다.
`trendTypes`, `description`, `summary`, `reason`은 요청 기간 지표 유무와 관계없이 반환한다.
이는 실제 언급량이 0인 지표와 구분된다. 성공 응답의 `message`도 기존 계약대로 `null`이다.
`summary` 또는 `reason`이 아직 저장되지 않았다면 해당 필드는 `null`이며 예시 데이터를 생성하지 않는다.

==== 400 Bad Request — 기간 누락 또는 오류

operation::trends-detail-invalid-period[snippets='http-response,response-fields']

==== 400 Bad Request — 잘못된 ID

트렌드 ID가 양의 정수가 아니거나 Long 범위를 벗어나면 반환한다.

operation::trends-detail-invalid-id[snippets='http-response,response-fields']

==== 404 Not Found — 트렌드 없음

operation::trends-detail-not-found[snippets='http-response,response-fields']

==== 인증 연동

인증이 필요한 API이며, 서비스는 로그인 사용자 정보를 사용하지 않는다.
`Authorization: Bearer <액세스 토큰>` 헤더로 호출하며, 토큰 검증은 공통 인증 필터가 담당한다.
토큰이 없거나 유효하지 않으면 공통 오류 구조로 401을 반환한다.
문서 테스트는 Spring Security의 테스트용 인증 컨텍스트를 사용하므로 예시 Bearer 헤더 값 자체가 검증되지는 않는다.

[[trends-history]]
=== 관심도 시계열 조회

`GET /trends/{trendId}/history?period={period}`

`period`는 필수이며 `24H`, `7D`, `30D`만 허용한다. `Asia/Seoul`의 오늘 자정을 종료 시각으로 삼아
완료된 직전 1일, 7일 또는 30일을 조회한다. `24H`는 1시간 단위 24개, `7D`는 1일 단위 7개,
`30D`는 3일 단위 10개 버킷이다. 각 항목은 `bucketStart`, `bucketEnd`, `mentionCount`를 반환한다.

==== 요청 및 응답

operation::trends-history[snippets='http-request,request-headers,path-parameters,query-parameters,http-response,response-fields']

전체 조회 구간을 오름차순으로 구성한다. `keyword_metric_history`의 키워드 시계열을 조회하며,
3일 버킷은 범위 내 저장 언급량을 합산한다. 해당 버킷에 키워드 언급 데이터가 없으면
`mentionCount`는 `0`이다.
트렌드 자체가 없을 때만 404를 반환한다.

[[trends-contents]]
=== 트렌드 관련 콘텐츠 조회

`GET /trends/{trendId}/contents?page={page}&size={size}`

트렌드의 키워드와 `keyword_contents`로 연결된 콘텐츠를 게시 시각 내림차순으로 조회한다.
게시 시각이 같으면 콘텐츠 ID 내림차순으로 정렬한다. 페이지 번호의 기본값은 0, 페이지 크기의 기본값은 10이다.

==== 요청 및 응답

operation::trends-contents[snippets='http-request,request-headers,path-parameters,query-parameters,http-response,response-fields']

관련 콘텐츠가 없으면 200과 빈 `content`를 반환한다. 트렌드 자체가 없을 때만 404를 반환한다.

[[trends-related-keywords]]
=== 트렌드 연관 키워드 조회

`GET /trends/{trendId}/related-keywords`

트렌드의 키워드를 source로 하는 `keyword_relations`의 연관 키워드를 관계 점수 내림차순으로 조회한다.
관계 점수는 0~100 범위에서 소수 둘째 자리까지 사용한다.
점수가 같으면 키워드 ID 오름차순으로 정렬하며 source와 target이 같은 자기 참조 관계는 제외한다.

==== 요청 및 응답

operation::trends-related-keywords[snippets='http-request,request-headers,path-parameters,http-response,response-fields']

연관 키워드가 없으면 200과 빈 `relatedKeywords`를 반환한다. 트렌드 자체가 없을 때만 404를 반환한다.

`DELETE /members/me/interest-keywords/{interestKeywordId}`

로그인한 회원이 직접 등록한 관심 키워드를 삭제한다.

=== 관심 키워드 기반 추천 키워드 조회

`GET /members/me/recommended-keywords`

[[keywords-search]]
=== 키워드 검색

`GET /keywords/search?query={query}&domain={domain}&page={page}&size={size}`

키워드명을 대소문자 구분 없이 부분 일치로 검색한다. 정확히 일치하는 키워드를 먼저 반환하고,
그 다음에는 키워드 ID 오름차순으로 정렬한다. `domain`은 선택 사항이며 `DEVELOP`, `FASHION`을 지원한다.
페이지 번호의 기본값은 0, 페이지 크기의 기본값은 20이다.
예를 들어 `ai`, `AI`, `Ai`는 동일하게 검색하며, `ai`로 검색하면 `AI Agent`, `AI Coding`이 포함될 수 있다.
한영 별칭이나 동의어 확장은 적용하지 않는다.

==== 요청 및 응답

operation::keywords-search[snippets='http-request,request-headers,query-parameters,http-response,response-fields']

검색 대상은 현재 트렌드 여부와 관계없는 전체 `keywords`다. 현재 트렌드인 키워드는 트렌드 ID와 유형,
`Asia/Seoul` 기준 완료된 최근 24시간 지표의 증가율을 함께 반환한다. 트렌드가 아니면 `trendId`와
`growthRate`는 `null`, `trendTypes`는 빈 배열이다. 검색 결과가 없으면 200과 빈 `content`를 반환한다.

=== 로그인

`accessTokenExpiresIn`과 `refreshTokenExpiresIn`은 발급 시점 기준의 유효 기간이며 단위는 초다.

[[auth-reissue]]
=== 토큰 재발급

`POST /auth/reissue`

유효한 리프레시 토큰을 새 액세스 토큰과 리프레시 토큰 한 쌍으로 교환한다. 인증 헤더 없이 호출한다.

리프레시 토큰은 재발급할 때마다 회전한다. 요청에 사용한 리프레시 토큰은 응답을 받은 시점부터 무효이므로,
클라이언트는 응답의 `refreshToken`으로 반드시 교체해야 한다. 유효 기간은 재발급 시점부터 다시 계산된다.

리프레시 토큰은 회원당 하나만 유효하다. 다른 기기에서 로그인하거나 재발급하면 이전 토큰은 무효가 된다.

[[auth-logout]]
=== 로그아웃

`POST /auth/logout`

현재 로그인 세션을 종료한다. 액세스 토큰으로 인증한 뒤, 그 세션의 리프레시 토큰을 본문으로 함께 보낸다.

저장된 리프레시 토큰을 삭제하므로 이후 재발급은 실패한다.
액세스 토큰은 상태를 두지 않으므로 이미 발급된 토큰은 남은 유효 기간(최대 15분) 동안 그대로 동작한다.
클라이언트는 로그아웃 응답을 받으면 보관 중인 액세스 토큰과 리프레시 토큰을 모두 폐기해야 한다.

본문의 리프레시 토큰은 액세스 토큰과 같은 회원의 것이어야 하며, 현재 세션의 토큰이어야 한다.
이미 로그아웃했거나 재발급으로 회전된 토큰을 보내면 401을 반환한다.

===== 401 Unauthorized — 세션 불일치

리프레시 토큰이 유효하지 않거나, 다른 회원의 토큰이거나, 현재 세션과 일치하지 않는 경우.
어느 경우인지 구분해 노출하지 않는다.

operation::auth-logout-invalid-token[snippets='http-response,response-fields']
