[[trends]]
== Trends

[[trends-detail]]
=== 트렌드 상세 조회

`GET /trends/{trendId}?period={period}`

`period`는 필수이며 `24H`, `7D`, `30D`만 허용한다. 대시보드에서 선택한 기간을 그대로 전달한다.
상세 지표는 `Asia/Seoul` 기준 완료 구간과 일치하는 분석 결과를 사용하며,
같은 구간의 분석이 여러 개이면 최신 분석을 선택한다. 분석 시각(`analyzedAt`)이 같으면 더 큰 분석 ID를 선택한다.
`description`은 트렌드의 짧은 설명이고, `aiAnalysis.summary`는 관련 콘텐츠에서 생성한 별도의 AI 요약이다.
`aiAnalysis`는 요청 기간과 무관하게 해당 트렌드에 저장된 최신 AI 분석 결과다.
분야는 기존 회원 도메인의 `DEVELOP`, `FASHION` 코드를 사용하며 중분류는 없다.

==== 요청

operation::trends-detail[snippets='http-request,request-headers,path-parameters,query-parameters']

==== 200 OK

operation::trends-detail[snippets='http-response,response-fields']

분석 구간은 `Asia/Seoul` 자정 기준의 완료된 연속 구간이며, 요청 기간과 그 직전 동일 기간을 비교한다.
증가량은 요청 기간 언급량에서 직전 동일 기간 언급량을 뺀 값이다.
증가율은 `(증가량 / 직전 언급량) × 100`을 소수 둘째 자리에서 반올림하여 소수 첫째 자리까지 표시한다.
직전 언급량이 0이면 `growthRate`는 `null`이다.
시각은 오프셋을 포함하는 ISO 8601이며 분석 구간은 시작 포함, 종료 제외이다.

==== 200 OK — 요청 기간 분석 없음

트렌드가 존재하면 기본 정보를 반환한다.
`trendType`, 언급량·증가량·증가율, `analysisWindow`, `analyzedAt`, `evidence`는 모두 명시적인 `null`이다.
최신 AI 분석이 존재하면 `aiAnalysis`는 요청 기간 분석 유무와 관계없이 반환한다.
이는 실제 언급량이 0인 분석과 구분된다. 성공 응답의 `message`도 기존 계약대로 `null`이다.
분석이 있더라도 판정 근거나 AI 결과를 아직 저장하지 않았다면 각각 `null`이며, 예시 데이터를 생성하지 않는다.

==== 인증 연동

인증이 필요한 API이며, 서비스는 로그인 사용자 정보를 사용하지 않는다.
`Authorization: Bearer <액세스 토큰>` 헤더로 호출하며, 토큰 검증은 공통 인증 필터가 담당한다.
토큰이 없거나 유효하지 않으면 공통 오류 구조로 401을 반환한다.
문서 테스트는 Spring Security의 테스트용 인증 컨텍스트를 사용하므로 예시 Bearer 헤더 값 자체가 검증되지는 않는다.

[[trends-history]]
=== 관심도 시계열 조회

`GET /trends/{trendId}/history?period={period}`

`period`는 필수이며 `24H`, `7D`, `30D`만 허용한다. `Asia/Seoul`의 오늘 자정을 종료 시각으로 삼아
완료된 직전 1일, 7일 또는 30일을 조회한다. `24H`는 시간 단위, 나머지는 일 단위 버킷이다.

==== 요청 및 응답

operation::trends-history[snippets='http-request,request-headers,path-parameters,query-parameters,http-response,response-fields']

저장된 버킷이 하나 이상 있으면 전체 조회 구간을 오름차순으로 구성하고 `dataStatus`를 `AVAILABLE`로 반환한다.
해당 버킷에 트렌드 언급 데이터가 없으면 `mentionCount`는 `0`이다.
조회 구간에 버킷 행이 전혀 없으면 `NO_DATA`와 빈 `history`를 반환한다.
트렌드 자체가 없을 때만 404를 반환한다.

[[auth-login]]
=== 로그인

이메일·비밀번호로 액세스 토큰과 리프레시 토큰을 발급한다.
계정 존재 여부를 구분해 노출하지 않으므로, 가입되지 않은 이메일과 비밀번호 불일치는 같은 401 응답을 반환한다.

리프레시 토큰은 회원당 하나만 유효하다. 다시 로그인하면 이전에 발급한 리프레시 토큰은 무효가 된다.
`accessTokenExpiresIn`과 `refreshTokenExpiresIn`은 발급 시점 기준의 유효 기간이며 단위는 초다.

[[auth-reissue]]
=== 토큰 재발급

`POST /auth/reissue`

유효한 리프레시 토큰을 새 액세스 토큰과 리프레시 토큰 한 쌍으로 교환한다. 인증 헤더 없이 호출한다.

리프레시 토큰은 재발급할 때마다 회전한다. 요청에 사용한 리프레시 토큰은 응답을 받은 시점부터 무효이므로,
클라이언트는 응답의 `refreshToken`으로 반드시 교체해야 한다. 유효 기간은 재발급 시점부터 다시 계산된다.

리프레시 토큰은 회원당 하나만 유효하다. 다른 기기에서 로그인하거나 재발급하면 이전 토큰은 무효가 된다.

===== 401 Unauthorized
