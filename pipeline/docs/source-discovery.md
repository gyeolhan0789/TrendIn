# 소스 발견 — 프로필과 등록

수집할 사이트를 늘리는 일을 **프로필 파일 하나 + PR 하나**로 만든다. AI 는 그 파일을 쓰고 고치는 데만 쓴다.
`web-collect.md` 가 "소스에서 어떻게 받나"의 계약이라면, 이 문서는 "소스 목록이 어떻게 자라나"의 계약이다.

- 결정일: 2026-09-07. 실측은 그날 저장돼 있던 픽스처 기준이다.
- 근거 등급 표기: ① 실행 결과 ② 출처 ③ 감. 표기가 없는 줄은 이 문서의 결정이다.
- 잠정값은 **(잠정)** 으로 표시한다.
- 뒤집힌 결정은 취소선과 날짜로 남기고, 없어진 번호는 결번으로 둔다 — 코드 주석이 번호로 부른다.

## 2. 왜 링크로 사이트를 못 찾나 (① 실측 2026-09-07)

저장된 픽스처로 아웃바운드 링크를 셌다. 패션 매거진은 **본문에서 다른 매체로 링크하지 않는다.**

| 소스 | 표본 | 본문 외부 링크 |
|---|---|---|
| vogue · wkorea · allure · marieclaire | 기사 12건, 본문 5,239자 | 0 |
| gqkorea | 기사 3건, 본문 1,130자 | 1 (gq.com — 본사) |
| harpersbazaar · cosmopolitan | 페이지 5장 | 39~52개인데 전부 껍데기 |

목록 페이지 39개 · 기사 페이지 40개 · 다른 기사 40개로 **거의 같다.** 본문이 아니라 네비게이션·푸터라는 뜻이다.
실제 도메인은 `hjmembers`(회원) · instagram/twitter/facebook/youtube(공유) · avatye(광고) · `elle.co.kr` · `esquirekorea.co.kr` 다.

**그 잡음이 다른 신호다.** 전 페이지에 똑같이 나오는 도메인은 같은 발행사의 **자매지**다.
`elle` · `esquire` 는 허스트중앙이고, 두산매거진 4곳은 이미 다 갖고 있다.
자매지는 같은 템플릿을 쓰므로 어댑터가 재사용된다 — 발견과 구현이 같은 신호에서 나온다.

**dev 는 방향이 반대다.** Hacker News 는 그 자체가 아웃바운드 링크 집계기고, 스토리 하나가 곧 외부 URL 하나에 점수까지 붙어 온다.
같은 신호가 도메인에 따라 뜻이 다르다 — 그래서 발견 경로도 도메인마다 다르다.

## 3. 프로필

소스 하나가 파일 하나다. `src/trendin/<domain>/collect/sources/<key>.toml`.

파일당 하나인 이유는 **PR 이 동시에 여러 개 열리기 때문**이다. 한 파일이면 후보 PR 끼리 매번 충돌한다.
자가 치유 PR 도 파일 하나만 고쳐서 diff 가 곧 "이 사이트의 무엇이 바뀌었나"가 된다.

TOML 인 이유는 둘이다. `tomllib` 이 stdlib 이라 의존성이 안 늘고, YAML 의 암묵 타입 변환이 이 프로필에서 실제로 물린다 —
`guid_param = y` 가 불리언이 되고 `no` · `on` · `off` 도 같은 함정이다. 프로필에 들어가는 게 클래스 이름·쿼리 파라미터·도메인이라 정확히 그 지뢰밭이다.

2026-09-17 S15P21A102-284 설계 합의로 정한 것:

- 규칙 칸은 인라인 테이블이다. `article_id = { rule = "guid_query_param", param = "p" }`.
- `sources.py` 는 `sources/__init__.py` 로 옮기고 프로필 TOML 은 같은 폴더에 둔다. 목록 소스(허스트 2곳)는 `__init__.py` 코드에 남는다.
- 로더는 모르는 키를 거부한다. `country` 는 두 글자 대문자 또는 `XX`, `allowed_url_prefixes` 는 필수, `license` 는 선택이되 쓰면 이름·근거 URL·검토일 셋을 다 쓴다.
- 프로필 하나라도 깨지면 로더 전체가 실패한다. 한 소스만 조용히 빠지면 아무도 모르기 때문이다(확정 8).

### 3.1 칸

| 칸 | 필수 | 내용 |
|---|---|---|
| `key` `domain` `route` | ✓ | `SourceDef` 와 같다. 파일 이름이 `key` 다 |
| `discover_url` `allowed_url_prefixes` | ✓ | 위와 같다 |
| `article_id` | ✓ | 규칙 이름 + 파라미터. #3.2 |
| `published_at` | ✓ | 위와 같다 |
| `page_param` | | 피드 페이지 넘김 쿼리 파라미터. 없으면 페이지 넘김이 안 되는 피드다. 기존 5곳은 `paged`, 새 소스 값은 S15P21A102-290 이 채운다 (2026-09-17 284 합의) |
| `country` | ✓ | 발행 법인 소재지. ISO 3166-1 alpha-2, 판정 불가는 `XX`. `SourceDef.country` 와 같다(`web-collect.md` #10) (2026-09-17 추가) |
| ~~`body`~~ | | **철회 (2026-09-17).** 본문은 추출 순서로 얻는다(`web-collect.md` 확정 2). 옛 칸: 본문 위치. `tag` \| `id` \| `class` 중 하나 + 걷어낼 클래스 목록 |
| `license` | | 라이선스 이름. 근거 URL 과 검토일이 함께 온다. CC 등 라이선스를 밝힌 소스만 채운다 (2026-09-17 필수 해제) |
| ~~`terms`~~ | | **철회 (2026-09-17).** 약관은 판정 기준이 아니다. 옛 칸: 약관 URL, 자동 수집 금지 문구 유무, 검토일 |
| ~~`body_allowed`~~ | | **철회 (2026-09-17).** 게이트2 폐지. 옛 칸: 게이트2 통과 여부 |

`license` 가 프로필에 있는 이유는 **소스가 20개가 되면 설계 문서의 표가 안 따라오기 때문**이다. 저작권 쪽 근거(`web-collect.md` 불변식 11·12)는 기준 전환 뒤에도 살아 있다.
소스를 지울 때 근거도 같이 지워지고, 추가할 때 빈칸이 강제된다. 검토일이 있으면 오래된 검토를 기계가 골라낼 수 있다.

### 3.2 추출 규칙은 열거형이다

정규식을 넣지 않는다. `article_id` 는 `guid_query_param` · `url_path_segment` · `api_field` · `guid_hash` 중 하나,
`published_at` 은 `rss_pubdate` · `dc_date` · `atom_published` · `atom_updated` · `meta_property` · `ldjson_field` 중 하나를 고르고 파라미터만 채운다.

| 규칙 | 뜻 |
|---|---|
| `guid_hash` | guid 만 쓴다(Atom 은 `<id>`, RSS 1.0 은 `rdf:about`). 앞뒤 공백만 벗기고 sha256 앞 16자. 비면 그 item 은 발견 단계 실패이고 `link` 로 넘어가지 않는다 — 필요해지면 `link_hash` 를 따로 더한다. 슬러그만 있는 URL(vogue_us 등)은 제목이 바뀌면 id 가 바뀌어서 둔다 (2026-09-17 284 합의) |
| `rss_pubdate` | `pubDate`, RFC 822 |
| `dc_date` | `dc:date`, ISO 8601 (2026-09-17 284 합의) |
| `atom_published` · `atom_updated` | Atom `<published>` · `<updated>` (2026-09-17 284 합의) |
| `meta_property` · `ldjson_field` | 기사 페이지를 받아야 쓸 수 있다. S15P21A102-285 이후 |

**프로필은 발행일 규칙을 하나만 고르고 대체 순서는 없다.** 리뷰어가 프로브로 규칙을 확인한다는 열거형의 근거를, 코드에 숨은 대체 순서가 건너뛰기 때문이다 (2026-09-17 284 합의).

이 설계의 실제 비용은 코드가 아니라 **AI 산출물을 사람이 리뷰하는 시간**이다.
열거형이면 리뷰가 "이 사이트가 진짜 `url_path_segment` 인가"를 프로브 샘플 3건으로 보는 일이 된다.
정규식이면 리뷰어가 머릿속에서 정규식을 실행해야 하고, 3건에서 통과한 뒤 네 번째에서 조용히 틀린다.
**열거형은 기계가 검증한다** — 프로브 3건에 규칙을 적용해 하나라도 비면 PR 이 안 열린다.

### 3.3 선택자 — 철회 (2026-09-17)

본문 위치 선택자를 프로필에서 뺐다. 본문은 피드 전문 → ld+json `articleBody` → trafilatura 순서로 얻는다(`web-collect.md` 확정 2).
이 절의 근거였던 "파서 의존성을 늘리지 않는다"는 trafilatura 2.2.0(lxml 의존)을 들이면서 무너졌다. 아래는 옛 결정이다.

> 레포에 BeautifulSoup·lxml 이 없고 `html_text.py` 가 stdlib `html.parser` 위에 있다. CSS 셀렉터 엔진이 없다.
>
> 그래서 본문 위치는 **태그·id·클래스 셋 중 하나**로 지정하고 조합(자손 선택자)을 금지한다.
> 조합을 허용하는 순간 CSS 엔진이 필요하고 그건 의존성 추가다. 셋 중 하나로 닫으면 파서를 안 바꾸고
> `<article>` 태그만 있는 블로그와 `id="content"` 쓰는 사이트가 살아난다 — dev 확장에 특히 그렇다.

## 4. 등록

게이트는 등록 하나다. 등록을 통과한 소스는 처음부터 본문과 raw 를 저장한다 — 회원 전용·유료 표시 기사만 뺀다(`web-collect.md` 불변식 2).

| | 등록 |
|---|---|
| 단위 | 국가별로 묶은 PR 하나 |
| 통과하면 | 제목·URL·발행일·요약·본문·raw 를 모은다 |
| 사람이 보는 것 | 측정 표(피드 종류, 피드 전문 비율, 기사 추출 결과), 어댑터 종류, **프로브 3건 결과** |
| 기계가 채우는 것 | 측정 표와 프로브 결과 |
| 자동 탈락 | 첫 요청이 403·429 인 곳(불변식 2). robots.txt 는 기록만 한다 |

측정 표의 모양은 `source-survey-2026-09-16/` 이 처음 만들었고(① 81곳), 291 의 PR 이 이 표를 붙인다.

**게이트2 를 없앤 것은 2026-09-17 기준 전환 결정이다.** 옛 게이트2 는 등록한 소스에서 모은 제목 표본 50건으로 쓸모를 본 뒤 본문을 받게 하는 장치였다.
폐지하면서 쓸모 판정은 등록 때의 측정 표로 당겼다. 옛 두 게이트 표, "본문 승인은 소급하지 않는다"는 규칙, 게이트2 자동 지표(#12-2)는 이 결정으로 없어졌다.

### 5.1 HN 이 링크한 원문 (백로그)

승인된 도메인은 **원문 취득 화이트리스트**로 쓴다. 독립 소스로 만들지 않는다.

HN 이 URL 을 주므로 발견 경로가 필요 없고 프로필이 절반 크기다. "HN 에 올라왔다"가 품질 필터로 공짜로 딸려 온다.
HN 매개라는 편향은 이 프로젝트에 맞는 편향이다 — 재려는 게 dev 트렌드고 HN 점수는 그 지표지 잡음이 아니다.

저장 키는 `{domain}/{그 도메인 키}/linked/…` 다. `source` 를 `hn` 으로 두면 사이먼 윌리슨 글의 출처가 `hn` 이 되는데,
그건 출처가 아니라 경유지다. 저작권법 제37조를 위해 넣은 필드가 틀린 값을 담으면 그 필드를 없앤 것과 같다(불변식 11).

## 6. 자가 치유

사이트 구조는 바뀐다. `web-collect.md` 도 "#2 의 표는 그날의 사실"이라고 못 박았다.
그런데 불변식 9 가 "필수 필드가 하나라도 비면 저장하지 않고 실패로 남긴다"라, 구조가 바뀌면 **그 소스가 조용히 멈춘다.**

| 탐지 | 잡는 고장 | 계산 |
|---|---|---|
| 저장 0건이 2회 연속 | 발견 자체가 깨졌다 | `SourceOutcome.stored` |
| 한 실행의 실패율이 문턱을 넘음 **(잠정 0.8)** | 발견은 되는데 정규화가 깨졌다 | `failures` / `candidates` |

둘 다 `SourceOutcome` 이 이미 들고 있는 값으로 계산되고, 신호를 낼 자리도 있다 —
`fashion_collect` 의 `publish` 태스크가 이미 `xcom_pull` 로 죽은 소스를 집계한다.

**새 글이 없어서 0건인 것과 깨져서 0건인 것**을 갈라야 한다. `not_modified`(304)와 `skipped`(장부에 이미 있음)가 구분해 준다 —
후보는 나왔는데 저장이 0이면 깨진 것이고, 후보 자체가 0이면 정상일 수 있다.

복구는 사람이 `propose.py` 를 돌려 프로필 diff PR 을 만든다. 런타임은 프로필을 고치지 않는다.

| 부품 | 자리 | 계약 |

| 프로필 로더 | 프로필은 `<domain>/collect/sources/` 에 `__init__.py` 와 함께 둔다(#3, 2026-09-17 284 합의). 로더 모듈 자리는 284 가 정한다. ~~`common/collect/profiles.py` (신설)~~ | TOML → `SourceDef`. 디렉터리를 편 결과가 `SOURCE_KEYS` |
| 범용 목록 어댑터 (백로그) | `fashion/collect/listing.py` 개정 | 발견 URL 을 프로필에서 받는다. ~~허스트 2곳도 프로필로 내린다~~ (2026-09-17 확정 5 개정). ~~선택자를 프로필에서 받는다~~ (2026-09-17, #3.3 철회). 피드 없는 사이트는 282 에서 두 번째 묶음으로 미뤘다 |
| 공통 runner | `common/collect/runner.py` (이동) | 도메인이 인자다. 도메인별 runner 를 없앤다 |
| 프로브 세션 | `common/collect/session.py` 재사용 | 후보 도메인을 허용 접두어로 채운다 |

| 링크 행 (백로그) | 앱 DB `article_link` (신설) | `(source, article_id, linked_domain)` |
| 거절 기록 | `sources/rejected/<key>.toml` | 이유·근거 URL·검토일 |

**어댑터 종류는 플랫폼당 하나다.** 새 종류는 사이트 **3곳 이상**이 쓸 수 있을 때만 만든다.
근거는 이미 데이터에 있다 — WordPress 피드 하나가 5곳을, 허스트 템플릿 하나가 2곳을 먹었다.
어댑터가 사이트를 따라 늘면 폭증이고, 플랫폼을 따라 늘면 안 는다.

`route` 는 MinIO 객체 키에 영구히 박히므로(`keys.ROUTE_EXT`) 종류를 늘리는 건 공짜가 아니다.
되돌리려면 이미 저장된 객체를 옮겨야 한다.
